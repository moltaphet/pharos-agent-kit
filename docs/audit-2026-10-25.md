# Pharos Agent Kit — audit report (2026-10-25)

## Scope and result

Reviewed all 20 task engines, adapters, browser-facing data paths and shared infrastructure, then ran the task suites and added regressions for reproduced defects. Changes are on `codex/comprehensive-audit`; nothing was committed, pushed, or sent to a live chain.

The complete test command could not finish cleanly inside this environment: tests that bind `127.0.0.1` fail with `EPERM`, and two Foundry fork-start tests cannot start Anvil. Excluding those environment-dependent tests, **752 tests passed, 0 failed**. `node scripts/audit-static.mjs`, generated-submission checks (11/11), focused payment/invoice/recurring/liquidation tests (57/57), and `git diff --check` passed. A dependency audit earlier found zero production vulnerabilities after the Zod override; repeating `npm audit` at final verification was blocked by DNS failure to `registry.npmjs.org`.

## Shared infrastructure hardening

The request limiter releases capacity on synchronous exceptions and validates limits. RPC and HTTP handlers reject malformed envelopes/statuses and classify timeouts explicitly. Health probes coalesce concurrent cold requests and reject malformed block data. The local dev server bounds request bodies, reports malformed JSON, uses exact route matching, handles `HEAD`, and rejects unsafe paths and unsupported methods.

The submission task map now owns each added regression test exactly once; generated task READMEs and submission files were refreshed.

## Remaining verification limits

- Local HTTP integration tests require binding loopback sockets, which this execution sandbox blocks (`EPERM`). They were excluded from the 752-test passing run.
- Two Anvil startup/fork tests could not start Anvil in this environment. No live RPC/service availability was established during this audit.
- For hosted x402 deployments, nonce coordination across multiple facilitator instances depends on the configured dedicated `FACILITATOR_URL` service. That external service must provide its own shared nonce/idempotency coordination.
- `npm audit` could not be repeated after code changes because the npm registry hostname did not resolve. The earlier successful audit reported zero production vulnerabilities with the dependency override in place.
