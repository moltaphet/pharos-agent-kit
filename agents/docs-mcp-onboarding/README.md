# 3. Docs MCP Onboarding

> Onboard onto Pharos with nothing but its docs server, and report exactly where it let you down.

**Arena task:** Developer Docs MCP · Easy · [brief](https://pharos-agent-arena.vercel.app/tasks/docs-mcp-onboarding)  
**Try it:** https://pharos-agent-kit.vercel.app/#/docs-mcp-onboarding/try  ·  **Story, decisions and how to verify:** https://pharos-agent-kit.vercel.app/#/docs-mcp-onboarding

## What it does

The brief for this task is feedback: pretend to be a developer who knows nothing about Pharos, use only Developer Docs MCP, and write an honest account of where the docs got you unstuck and where they failed.

## What is real

Ten onboarding questions asked to Docs MCP; every documentation gap is confirmed by a live check against the network.

## Requirements and how each is met

| # | The Arena requires | How it is met |
|---|---|---|
| 1 | A step-by-step log of what you tried to do, the questions you asked Docs MCP, and the answers you got. | Every question, its exact wording and the docs’ answer appear in the log below, and in the downloadable report. |
| 2 | At least 3 concrete gaps or breakdowns (wrong, missing, or confusing answers), each with the exact query. | Gaps come from checks against the live network or the real URL, each listed with the exact query that exposed it. The recorded report (reports/docs-mcp-onboarding.md) lists 6; the count can change because Docs MCP answers are generated. |
| 3 | A suggested fix for each gap: what the docs should have said. | Each gap carries a written suggestion of what the docs should have said. |
| 4 | Ends with what you managed to build or run by the end. | The report ends with what the onboarding actually ran (MCP connection, both RPCs, live reads) and what it could not do, and why. |
